# نبض بازار — داشبورد تحلیل رمزارز

داشبورد ایستای RTL برای نمایش بازارهای عمومی Ramzinex. برنامه داده‌های قیمت بازار و OHLCV را از endpointهای عمومی دریافت می‌کند و برای هر نماد، تحلیل تکنیکال مستقل را در مرورگر می‌سازد.

## داده و تحلیل

- فهرست بازارها: `https://publicapi.ramzinex.com/exchange/api/v1.0/exchange/pairs`
- OHLCV هر بازار: `https://publicapi.ramzinex.com/exchange/api/v1.0/exchange/chart/tv/history` با `symbol`، بازهٔ کندلی و resolution یک‌ساعته. endpoint تاریخچه، هر بار یک نماد می‌پذیرد؛ درخواست‌ها با هم‌زمانی محدود ارسال می‌شوند و خطای یک بازار مانع تحلیل بقیه نیست.
- در هر refresh اطلاعات واقعی API دریافت/اعتبارسنجی و موتور `AnalysisEngine.analyze(candles, currentPrice)` برای هر بازار جداگانه اجرا می‌شود. انتخاب کارت فقط تحلیل و کندل همان نماد را نشان می‌دهد.
- اعتبارسنجی شامل timestamp مرتب و معتبر، OHLCV عددی و سازگار، حداقل ۱۲۰ کندل و تازگی داده است. خطای API، کندل ناکافی یا دادهٔ قدیمی به وضعیت دادهٔ نامعتبر و سیگنال `NEUTRAL` می‌انجامد؛ دادهٔ قدیمی به‌عنوان زنده نمایش داده نمی‌شود.
- موتور ۳۰ شاخص تکنیکال و ارزیابی walk-forward را از همان تاریخچه می‌سازد. پیش‌بینی‌ها در هر نقطه فقط از اطلاعات تا همان کندل استفاده می‌کنند و بازده پنج کندل بعد صرفاً برای ارزیابی گذشته به کار می‌رود.
- cache حافظه‌ای کوتاه‌مدت برای کاهش درخواست تکراری وجود دارد؛ خروجی تحلیلِ انتخاب‌شده از دادهٔ cache شده نیز دوباره محاسبه می‌شود. refresh خودکار به‌طور پیش‌فرض هر ۶۰ دقیقه است و UI گزینه‌های ۵، ۱۵، ۳۰ و ۶۰ دقیقه و زمان refresh بعدی/آخرین دریافت را دارد. دکمهٔ به‌روزرسانی refresh دستی انجام می‌دهد.
- نمودار، کندل‌های OHLCV واقعی API را رسم می‌کند. مقادیر متنی UI با `textContent` درج می‌شوند.

## اجرا و انتشار در GitHub Pages

1. `index.html`، `styles.css`، `app.js` و `analysis-engine.js` را در ریشهٔ مخزن قرار دهید.
2. در GitHub به **Settings → Pages** بروید و از branch و پوشهٔ ریشه انتشار دهید.
3. GitHub Pages فقط فایل‌های ایستا ارائه می‌کند. دسترسی مستقیم مرورگر به Ramzinex ممکن است به‌دلیل CORS، سیاست API، محدودیت جغرافیایی یا rate limit مسدود شود؛ در این حالت صفحه نمی‌تواند داده بگیرد و باید آن را در محیط مرورگر واقعی بررسی کرد.
4. راهکار پایدار، proxy کوچک server-side (مثلاً Cloudflare Worker یا سرویس backend خودتان) است که endpoint عمومی را واکشی و فقط دادهٔ موردنیاز را با CORS محدود و rate-limit کنترل‌شده به سایت برگرداند. هرگونه secret/API key باید فقط در متغیر محیطی سمت سرور بماند؛ هیچ API key یا secret در frontend قرار ندهید. endpoint proxy را در CONFIG فایل `app.js` تنظیم کنید.

## هشدار ریسک

این نرم‌افزار آموزشی/اطلاعاتی است و توصیهٔ سرمایه‌گذاری نیست. تحلیل تکنیکال، امتیاز و نرخ موفقیت تاریخی هیچ‌گونه تضمینی برای سود آینده ندارند. بازار رمزارز پرریسک است و مسئولیت تصمیم‌گیری با کاربر است.
